# SD Dance Studio — сайт по макету Figma

Готовый статический сайт танцевальной школы «SD Dance Studio» (Ялта), свёрстанный по макету
`sd studio` (Figma Sites, файл `wFCgeHl8bWNzRsk5kOVvoE`). Чистый HTML + CSS + немного JS:
без сборки, зависимостей и серверной части — файлы можно открыть локально или залить на любой
хостинг (в том числе GitHub Pages, Netlify, обычный shared-хостинг).

## Страницы

| Файл | Что это | Макет-источник |
| --- | --- | --- |
| `index.html` | Лендинг: о школе, dancehall, 3 причины, расписание групп, призыв, контакты | фрейм 1280×2885 + блок расписания |
| `groups.html` | Группы и тренеры: Ира, Даша и Соня, Катя + блок «большое комьюнити» | фрейм 1280×2627 |
| `plans.html` | «Выбери своё»: расписание по возрастам, стоимость абонементов, акции | фрейм 1280×1668 |

## Структура проекта

```
sd-studio/
  index.html  groups.html  plans.html     — страницы
  css/style.css                           — вся вёрстка (переменные, секции, адаптив)
  css/fonts.css                           — подключение локальных шрифтов
  js/main.js                              — мобильное меню, модальное окно записи, анимации
  assets/fonts/*.woff2                    — Oswald (дисплейный) и Onest (текстовый)
  assets/img/*                            — фото и вырезанные фигуры тренеров
  assets/favicon.svg
```

## Как посмотреть локально

Просто откройте `index.html` двойным щелчком. Если нужен локальный сервер (чтобы пути и
preload работали как на хостинге):

```bash
# из папки sd-studio
python -m http.server 8080
# затем http://localhost:8080
```

## Публикация на GitHub Pages

GitHub Pages раздаёт файлы репозитория как есть. Важно загрузить **все** файлы вместе с папками
`css`, `js` и `assets` — если залить только HTML-файлы, страница откроется без стилей и картинок
(именно это и происходит, когда наверху репозитория лежит один `index.html`).

Через веб-интерфейс:

1. Скачайте архив `sd-studio-site.zip` и распакуйте его.
2. В репозитории: **Add file → Upload files**, перетащите **содержимое** папки целиком —
   `index.html`, `groups.html`, `plans.html`, `README.md`, `.nojekyll` и папки `css`, `js`,
   `assets` → **Commit changes**.
3. Через минуту обновите страницу сайта с Ctrl+F5.

Проверьте, что в списке файлов репозитория появились папки `css`, `js`, `assets` — если их нет,
значит загрузились только отдельные файлы.

Через git (надёжнее):

```bash
git clone https://github.com/vanyaka229/sd-site.git
cd sd-site
# скопируйте сюда содержимое распакованного архива (с заменой index.html)
git add .
git commit -m "Полный сайт: стили, скрипты, изображения"
git push
```

Файл `.nojekyll` отключает обработку сайта через Jekyll — на случай, если в проекте появятся
файлы или папки с подчёркиванием в имени (Jekyll их игнорирует).

## Что учтено из макета

* **Палитра**: розовый `#FCC8F3`, маджента `#FB12A2`, чёрный, белый — вынесены в CSS-переменные.
* **Геометрия**: секции 80 / 167 / 480 / 115 / 600 / 480 / 479 px на ширине 1280 — совпадают
  с макетом покадрово; сетка «2/3 + 1/3» с чередованием сторон, как в макете.
* **Типографика**: размеры сняты с макета (заголовок 80 px, заголовки панелей 41/30 px,
  текст 17/15 px), крупные заголовки масштабируются от ширины экрана.
* **Адаптив**: три состояния — десктоп (≥1024, как макет 1280), планшет (768–1023, как макет 800),
  мобильный (<768, как макет 375) с бургер-меню «+».
* **Широкие экраны**: макет рассчитан на 1280 px, поэтому контент ограничен колонкой 1280 px по
  центру, а цветные полосы (розовые панели, маджента, фото) «разливаются» на всю ширину окна —
  текст и фигуры не разъезжаются на мониторах 1920 px и шире.
* **Текст поверх фигур**: подписи в панелях страницы «Группы» лежат выше вырезанных фото (как в
  макете), а рамки текстовых блоков взяты из макета так, чтобы строки не заходили на тёмную одежду.
* **Фото**: изображения вырезаны прямо из экспортов макета в 2× (папка `assets/img`). Снимки
  тренеров — PNG с прозрачным фоном: фон убран (в макете он не идеально однородный и
  прямоугольником читался бы как «коробка»), кромка сглажена, а там, где фигуру обрезает рамка
  кадра, край мягко растушёван — вместо жёсткой линии получается плавный переход в фон.
* **Интерактив**: модальное окно «Записаться на занятие» (Telegram и телефон), мобильное меню,
  плавный скролл, появление блоков при прокрутке, `prefers-reduced-motion`.

## Шрифты

В макете использован платный/непубличный шрифт (похож на Druk Condensed), поэтому взяты
свободные аналоги с полной кириллицей, максимально близкие по рисунку:

* **Oswald 500/700** — заголовки (в макете начертание чуть шире, поэтому в заголовках добавлен
  трекинг, чтобы ширина строк совпадала с макетом);
* **Onest 100–900** (вариативный) — текстовые блоки.

Оба шрифта распространяются по лицензии OFL и лежат локально в `assets/fonts` — интернет при
загрузке страницы не нужен. Чтобы поменять шрифт, отредактируйте `css/fonts.css` и переменные
`--display` / `--text` в начале `css/style.css`.


## Что добавлено к макету

* **Телефон и планшет**: фигуры тренеров больше не «плавают» поверх текста — на узких экранах
  каждая становится карточкой в обычном потоке, поэтому наездов нет ни на одной ширине.
* **Липкая кнопка «Записаться»** внизу экрана на телефоне, кнопка «наверх» после прокрутки.
* **Форма записи** в окне: имя, телефон, группа, комментарий; валидация и сообщение о результате.
* **Галерея** из настоящих фото студии на главной.
* **Анимации**: мягкое появление блоков при прокрутке, «лесенка» для соседей, увеличение фото
  при наведении, состояния нажатия и видимый фокус. Всё уважает `prefers-reduced-motion`.
* **Тап-цели** на телефоне не меньше 44 px.

## Приём заявок в Telegram

**Простой путь (по умолчанию).** В `js/main.js` в самом верху две строки:

```js
var TELEGRAM_BOT_TOKEN = '8936238994:AAE...'; // бот @sddance_journal_bot
var TELEGRAM_CHAT_ID = '8653239953';          // @sd_dancestudio — заявки идут сюда
```

Оба значения уже заполнены и проверены: заявка из формы доходит в Telegram.
Получателей можно перечислить через запятую: `'8653239953,123456789'`.

Как получить значения:

1. В Telegram найдите **@BotFather** → `/newbot` → скопируйте токен вида `7123456789:AAH3k...`.
2. Напишите своему боту любое сообщение (кнопка Start) — без этого бот не сможет вам писать.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и скопируйте число из
   `"chat": { "id": ... }`.

Всё: заявки из формы будут приходить вам в Telegram. Никаких серверов и аккаунтов больше не нужно.

Оговорка: в этом режиме токен виден в исходном коде страницы — так делают ради простоты.
Если бота начнут использовать для спама, перевыпустите токен у @BotFather (команда `/revoke`)
и замените строку. Более защищённый вариант — посредник, который держит токен у себя:
[deploy/README-telegram.md](deploy/README-telegram.md).

Пока строки пустые, форма открывает Telegram с готовым текстом заявки — это работает сразу,
но отправить сообщение нужно вручную.


## Если заявки не приходят

Автоматическая отправка идёт прямо из браузера посетителя на `api.telegram.org`. У части
провайдеров (в том числе в Крыму и ряде регионов РФ) этот адрес периодически недоступен —
тогда сообщение не уходит. Поэтому в форме есть мягкая страховка — **без слова «ошибка»**:

* запрос ограничен 7 секундами: если сеть «съела» его, посетитель видит
  «Заявка готова — отправьте её одним нажатием» и кнопку **«Отправить заявку в Telegram»**;
* кнопка ведёт на `https://t.me/sd_dancestudio?text=…` — это обычная ссылка в приложение
  Telegram, она работает на любом устройстве и **не требует доступа к `api.telegram.org`**;
  посетителю остаётся нажать «Отправить» в чате;
* при нажатии текст заявки ещё и копируется в буфер — если Telegram не установлен, письмо
  можно вставить в чат вручную;
* текст заявки сохраняется в `localStorage` (`sd_booking_ready`), поэтому он не теряется,
  даже если посетитель ушёл со страницы и вернулся;
* заявку с одного браузера нельзя отправить дважды в течение 30 секунд.

Логика в `js/main.js`: прямой запрос в `api.telegram.org` — первый, ручная ссылка — второй,
резервный путь. @username студии задаётся переменной `TELEGRAM_USERNAME`.

Если нужна гарантированная автоматическая доставка независимо от провайдера посетителя —
нужен посредник: сообщение уходит не из браузера, а с сервера. Готовый вариант лежит в
[deploy/](deploy/README-telegram.md) (можно разместить на российском хостинге, например Timeweb).

## Отзывы

Раздел отзывов свёрстан, но **выключен**: в `index.html` он закомментирован, потому что

## Что стоит заменить перед публикацией

1. **Ссылки на соцсети** — в футере и модальном окне указаны `instagram.com/sd_dancestudio`,
   `t.me/sd_dancestudio`, `t.me/danceyalta`, `tiktok.com/@sd_dancestudio`. Проверьте никнеймы.
2. **Телефон** `+7 (949) 033-24-31` — в футере и в модальном окне (`tel:`).
3. **Домен** — в `<link rel="canonical">` и Open Graph прописан заглушечный
   `https://sd-dance-studio.ru/`; замените на свой.
4. **Кнопка «Записаться»** сейчас открывает окно с Telegram и телефоном. Если нужна форма
   заявки — в это окно легко вставить `<form>` (разметка в конце каждой страницы).
5. **Фото на странице «Группы»** — блок «SD Studio — это не просто зал» содержит надпись,
   «вшитую» в изображение из макета (поэтому HTML-заголовок там скрытый — только для поисковиков
   и скринридеров). Для редактируемой надписи нужен исходный снимок без текста.
