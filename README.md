# SD Dance Studio — сайт по макету Figma

Готовый статический сайт танцевальной школы «SD Dance Studio» (Ялта), свёрстанный по макету
`sd studio` (Figma Sites, файл `wFCgeHl8bWNzRsk5kOVvoE`). Чистый HTML + CSS + немного JS:
без сборки, зависимостей и серверной части — файлы можно открыть локально или залить на любой
хостинг (в том числе GitHub Pages, Netlify, обычный shared-хостинг).

## Страницы

| Файл | Что это | Макет-источник |
| --- | --- | --- |
| `index.html` | Лендинг: о школе, dancehall, 3 причины, расписание групп, призыв, контакты | фрейм 1280×2885 + блок расписания |
| `groups.html` | Группы и тренеры: Ира, Даша и Соня, Катя + блок «большое комьюнити» | фрейм 1280×2627 |
| `plans.html` | «Выбери своё»: расписание по возрастам, стоимость абонементов, акции | фрейм 1280×1668 |

## Структура проекта

```
sd-studio/
  index.html  groups.html  plans.html     — страницы
  css/style.css                           — вся вёрстка (переменные, секции, адаптив)
  css/fonts.css                           — подключение локальных шрифтов
  js/main.js                              — мобильное меню, модальное окно записи, анимации
  assets/fonts/*.woff2                    — Oswald (дисплейный) и Onest (текстовый)
  assets/img/*                            — фото и вырезанные фигуры тренеров
  assets/favicon.svg
```

## Как посмотреть локально

Просто откройте `index.html` двойным щелчком. Если нужен локальный сервер (чтобы пути и
preload работали как на хостинге):

```bash
# из папки sd-studio
python -m http.server 8080
# затем http://localhost:8080
```

## Публикация на GitHub Pages

Сайт живёт на своём домене **https://sd-dance-st.ru/** (репозиторий раздаётся GitHub Pages).
Подробности — в разделе «Переезд на sd-dance-st.ru» ниже.

GitHub Pages раздаёт файлы репозитория как есть. Важно загрузить **все** файлы вместе с папками
`css`, `js` и `assets` — если залить только HTML-файлы, страница откроется без стилей и картинок
(именно это и происходит, когда наверху репозитория лежит один `index.html`).

Через веб-интерфейс:

1. Скачайте архив `sd-studio-site.zip` и распакуйте его.
2. В репозитории: **Add file → Upload files**, перетащите **содержимое** папки целиком —
   `index.html`, `groups.html`, `plans.html`, `README.md`, `.nojekyll`, `CNAME`, `robots.txt`,
   `sitemap.xml`, `og-preview.jpg` и папки `css`, `js`, `assets` → **Commit changes**.
3. Через минуту обновите страницу сайта с Ctrl+F5.

Проверьте, что в списке файлов репозитория появились папки `css`, `js`, `assets` — если их нет,
значит загрузились только отдельные файлы. Файл `CNAME` удалять нельзя: без него Pages забудет
свой домен.

Через git (надёжнее):

```bash
git clone https://github.com/vanyaka229/sd-site.git
cd sd-site
# скопируйте сюда содержимое распакованного архива (с заменой index.html)
git add .
git commit -m "Полный сайт: стили, скрипты, изображения"
git push
```

Файл `.nojekyll` отключает обработку сайта через Jekyll — на случай, если в проекте появятся
файлы или папки с подчёркиванием в имени (Jekyll их игнорирует).

## Переезд на sd-dance-st.ru

Домен куплен в Timeweb Cloud; хостинг остаётся на GitHub Pages, поэтому переезд — это DNS-записи
плюс настройка Pages. В репозитории для этого уже лежат:

* **`CNAME`** в корне сайта — ровно `sd-dance-st.ru` (14 байт, без протокола, слэша, пробелов и
  переводов строк). Удалять его нельзя: он и есть привязка домена к Pages.
* **`robots.txt`** — разрешает обход и указывает на `https://sd-dance-st.ru/sitemap.xml`.
* **`sitemap.xml`** — три страницы: `/`, `/groups.html`, `/plans.html`.
* **`og-preview.jpg`** — превью ссылки 1200×630 переехало в корень сайта, потому что в разметке
  указан адрес `https://sd-dance-st.ru/og-preview.jpg`.

### Записи DNS (панель Timeweb)

| Тип | Имя | Значение | TTL |
| --- | --- | --- | --- |
| A | `@` | `185.199.108.153` | 3600 |
| A | `@` | `185.199.109.153` | 3600 |
| A | `@` | `185.199.110.153` | 3600 |
| A | `@` | `185.199.111.153` | 3600 |
| CNAME | `www` | `vanyaka229.github.io` | 3600 |
| A | `api` | `<IP вашего VPS>` | 300–600 |

Это официальные адреса GitHub Pages: четыре A для самого домена и CNAME для `www`, чтобы
`www.sd-dance-st.ru` тоже открывался. Время расхождения DNS — обычно от нескольких минут до пары
часов.

Последняя строка — поддомен для приёмника заявок на VPS (`api.sd-dance-st.ru`, см.
[deploy/VPS-ПРИЁМНИК.md](deploy/VPS-ПРИЁМНИК.md)). IP подставляется, когда VPS выбран. Через API
Timeweb запись добавляется так — для поддоменов годится короткое имя, а для корня API требует
полное (`sd-dance-st.ru`), иначе отдаёт `400 bad_subdomain_name`:

```
POST https://api.timeweb.cloud/api/v1/domains/sd-dance-st.ru/dns-records
{ "type": "A", "value": "<IP VPS>", "ttl": 600, "subdomain": "api" }
```

### Приёмник заявок на VPS

В Крыму и у части провайдеров РФ браузер посетителя не может достучаться до `api.telegram.org`.
Поэтому заявка сначала уходит на наш приёмник `https://api.sd-dance-st.ru/tg`, а он уже сам
пересылает её в Telegram. Порядок попыток в `js/main.js`:

1. приёмник (`BOOKING_SERVER`, таймаут 5 с) — успехом считается только ответ `{"ok":true}`;
2. `api.telegram.org` напрямую (таймаут 7 с) — если приёмник недоступен;
3. мягкий режим «Заявка готова, отправьте одним нажатием» — если не сработало ничего.

Адрес приёмника меняется в одном месте — константа `BOOKING_SERVER` в начале `js/main.js`.
Код приёмника, юнит systemd, конфиг nginx и пошаговая инструкция для VPS —
[deploy/VPS-ПРИЁМНИК.md](deploy/VPS-ПРИЁМНИК.md); автотест без сервера — `test_vps_receiver.cjs`.
Вариант для App Platform (тот же приёмник в контейнере, HTTPS из коробки) — `Dockerfile`
в корне и [deploy/ПРИЁМНИК-ЧЕРЕЗ-APP-PLATFORM.md](deploy/ПРИЁМНИК-ЧЕРЕЗ-APP-PLATFORM.md).

> **8 октября 2026: путь через VPS остановлен** — порт 443 на сервере занят VPN-контейнером
> Amnezia (xray/Reality), HTTPS для приёмника там не поднять.

### Настройки Pages в репозитории

1. **Settings → Pages → Custom domain**: впишите `sd-dance-st.ru` → **Save**. GitHub проверит DNS
   и сам положит/обновит файл `CNAME`.
2. Дождитесь зелёной галочки проверки DNS (пока домен не разрешается, GitHub покажет
   «DNS check unsuccessful» — это нормально, проверка повторяется).
3. Включите **Enforce HTTPS**: сертификат Let's Encrypt выпускается автоматически, может занять
   до часа; до его готовности галочка недоступна.
4. Старый адрес `vanyaka229.github.io/sd-site/` после привязки домена сам перенаправляет на новый
   (301), репозиторий при этом остаётся с именем `sd-site` — переименовывать не нужно.

### Что проверить после включения домена

* `https://sd-dance-st.ru/` открывается по HTTPS без предупреждений сертификата;
* `http://` и `https://vanyaka229.github.io/sd-site/` перенаправляют на новый домен;
* `https://sd-dance-st.ru/og-preview.jpg` отдаётся по HTTPS (проверка: `check_meta.cjs` печатает
  строку «og:image по HTTPS»);
* работают все три страницы: `/`, `/groups.html`, `/plans.html`, горизонтальной прокрутки нет;
* в исходниках не осталось старого адреса — поиск по `github.io` и `sd-site` должен ничего не
  находить.

## Что учтено из макета

* **Палитра**: розовый `#FCC8F3`, маджента `#FB12A2`, чёрный, белый — вынесены в CSS-переменные.
* **Геометрия**: секции 80 / 167 / 480 / 115 / 600 / 480 / 479 px на ширине 1280 — совпадают
  с макетом покадрово; сетка «2/3 + 1/3» с чередованием сторон, как в макете.
* **Типографика**: размеры сняты с макета (заголовок 80 px, заголовки панелей 41/30 px,
  текст 17/15 px), крупные заголовки масштабируются от ширины экрана.
* **Адаптив**: три состояния — десктоп (≥1024, как макет 1280), планшет (768–1023, как макет 800),
  мобильный (<768, как макет 375) с бургер-меню «+».
* **Широкие экраны**: макет рассчитан на 1280 px, поэтому контент ограничен колонкой 1280 px по
  центру, а цветные полосы (розовые панели, маджента, фото) «разливаются» на всю ширину окна —
  текст и фигуры не разъезжаются на мониторах 1920 px и шире.
* **Текст поверх фигур**: подписи в панелях страницы «Группы» лежат выше вырезанных фото (как в
  макете), а рамки текстовых блоков взяты из макета так, чтобы строки не заходили на тёмную одежду.
* **Фото**: изображения вырезаны прямо из экспортов макета в 2× (папка `assets/img`). Снимки
  тренеров — PNG с прозрачным фоном: фон убран (в макете он не идеально однородный и
  прямоугольником читался бы как «коробка»), кромка сглажена, а там, где фигуру обрезает рамка
  кадра, край мягко растушёван — вместо жёсткой линии получается плавный переход в фон.
* **Домен**: свой адрес `https://sd-dance-st.ru/` (Timeweb), хостинг — GitHub Pages; в корне лежит
  `CNAME`, рядом `robots.txt` и `sitemap.xml`. См. раздел «Переезд на sd-dance-st.ru».
* **Шаринг**: Open Graph и `twitter:card: summary_large_image` на всех страницах, превью
  `og-preview.jpg` 1200×630 в палитре сайта с логотипом, микроразметка Schema.org `DanceSchool`
  (Ялта, телефон, Telegram).
* **Интерактив**: модальное окно «Записаться на занятие» (Telegram и телефон), мобильное меню,
  плавный скролл, появление блоков при прокрутке, `prefers-reduced-motion`.

## Шрифты

В макете использован платный/непубличный шрифт (похож на Druk Condensed), поэтому взяты
свободные аналоги с полной кириллицей, максимально близкие по рисунку:

* **Oswald 500/700** — заголовки (в макете начертание чуть шире, поэтому в заголовках добавлен
  трекинг, чтобы ширина строк совпадала с макетом);
* **Onest 100–900** (вариативный) — текстовые блоки.

Оба шрифта распространяются по лицензии OFL и лежат локально в `assets/fonts` — интернет при
загрузке страницы не нужен. Чтобы поменять шрифт, отредактируйте `css/fonts.css` и переменные
`--display` / `--text` в начале `css/style.css`.

## Приём заявок в Telegram

**Надёжный путь (по умолчанию).** Заявка сначала уходит на наш приёмник
`https://api.sd-dance-st.ru/tg`: он работает на VPS, у которого доступ к Telegram есть всегда,
и пересылает заявку в чат студии. Подробности и развёртывание —
[deploy/VPS-ПРИЁМНИК.md](deploy/VPS-ПРИЁМНИК.md). Если приёмник недоступен, сайт сам пробует
`api.telegram.org` напрямую, а если и это не вышло — показывает мягкий режим с кнопкой
(см. «Если заявки не приходят»).

**Прямой путь из браузера.** В `js/main.js` в самом верху две строки:

```js
var TELEGRAM_BOT_TOKEN = '8936238994:AAE...'; // бот @sddance_journal_bot
var TELEGRAM_CHAT_ID = '8653239953';          // @sd_dancestudio — заявки идут сюда
```

Оба значения уже заполнены и проверены: заявка из формы доходит в Telegram.
Получателей можно перечислить через запятую: `'8653239953,123456789'`.

Как получить значения:

1. В Telegram найдите **@BotFather** → `/newbot` → скопируйте токен вида `7123456789:AAH3k...`.
2. Напишите своему боту любое сообщение (кнопка Start) — без этого бот не сможет вам писать.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и скопируйте число из
   `"chat": { "id": ... }`.

Всё: заявки из формы будут приходить вам в Telegram. Никаких серверов и аккаунтов больше не нужно.

Оговорка: в этом режиме токен виден в исходном коде страницы — так делают ради простоты.
Если бота начнут использовать для спама, перевыпустите токен у @BotFather (команда `/revoke`)
и замените строку. Более защищённый вариант — посредник, который держит токен у себя:
[deploy/README-telegram.md](deploy/README-telegram.md).

Пока строки пустые, форма открывает Telegram с готовым текстом заявки — это работает сразу,
но отправить сообщение нужно вручную.


## Если заявки не приходят

Первый путь — приёмник на VPS (`https://api.sd-dance-st.ru/tg`): заявку в Telegram уводит сервер,
у которого доступ к `api.telegram.org` есть. Второй — прямой запрос из браузера посетителя:
у части провайдеров (в том числе в Крыму и ряде регионов РФ) этот адрес периодически недоступен,
и тогда сообщение не уходит. На этот случай в форме есть мягкая страховка — **без слова «ошибка»**:

* приёмник ждём 5 секунд, `api.telegram.org` — 7 секунд; если оба не ответили, посетитель видит
  «Заявка готова — отправьте её одним нажатием» и кнопку **«Отправить заявку в Telegram»**;
* кнопка ведёт на `https://t.me/sd_dancestudio?text=…` — это обычная ссылка в приложение
  Telegram, она работает на любом устройстве и **не требует доступа к `api.telegram.org`**;
  посетителю остаётся нажать «Отправить» в чате;
* при нажатии текст заявки ещё и копируется в буфер — если Telegram не установлен, письмо
  можно вставить в чат вручную;
* текст заявки сохраняется в `localStorage` (`sd_booking_ready`), поэтому он не теряется,
  даже если посетитель ушёл со страницы и вернулся;
* заявку с одного браузера нельзя отправить дважды в течение 30 секунд.

Логика в `js/main.js`: приёмник на VPS — первый, `api.telegram.org` — второй, ручная ссылка —
третий, резервный путь. @username студии задаётся переменной `TELEGRAM_USERNAME`.

Если нужна гарантированная автоматическая доставка независимо от провайдера посетителя —
нужен посредник: сообщение уходит не из браузера, а с сервера. Готовый вариант лежит в
[deploy/](deploy/README-telegram.md) (можно разместить на российском хостинге, например Timeweb).

## Ролик (выключен)

Блок с вертикальным роликом 9:16 лежит в `index.html` закомментированным — файл монтажа ещё
не готов. Постер `assets/img/reel-poster.jpg` (1080×1920, палитра сайта) и стили `.reel*`
в `css/style.css` уже на месте; видео грузится лениво (`preload="none"`), кадр строго 9:16.
Чтобы включить: положите ролик в `assets/video/sd-studio-reel.mp4` и снимите комментарий
вокруг `<section class="sec band reel" id="reel">`. Постер можно заменить настоящим кадром:

```bash
ffmpeg -ss 00:00:02 -i ролик.mp4 -frames:v 1 -vf scale=1080:-2 assets/img/reel-poster.jpg
```

На сайт идёт **веб-версия** ролика: мастер (117 МБ, для Instagram и YouTube) в репозиторий
не кладём — GitHub отклоняет файлы больше 100 МБ. Перекодировка из мастера:

```bash
ffmpeg -y -i <мастер>.mp4 -c:v h264_nvenc -preset p5 -rc vbr \
  -b:v 4500k -maxrate 7000k -bufsize 14000k -pix_fmt yuv420p -profile:v high \
  -movflags +faststart -c:a aac -b:a 128k -ar 48000 -ac 2 assets/video/sd-studio-reel.mp4
```

Замер на пробном прогоне (80 с, 1080×1920, NVENC): **44,9 МБ, кодирование 19 с** — попадает
в цель 35–50 МБ. `-movflags +faststart` обязателен: без него видео начнёт играть только после
полной загрузки. Вариант на CPU — `-c:v libx264 -preset slow -crf 23` вместо строки NVENC.
