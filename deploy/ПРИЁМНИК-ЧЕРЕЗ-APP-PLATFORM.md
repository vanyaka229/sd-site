# Приёмник заявок через App Platform (инструкция владельцу)

Коротко: **продукта «Функции/serverless» у Timeweb Cloud нет** — ни в каталоге услуг, ни в Public API
(проверено 8 октября: `POST/GET /api/v1/functions`, `/api/v2/functions`, `/api/v1/serverless`,
`/api/v1/faas` отвечают 404; в официальном SDK нет ни одной модели про функции).
Ближайшая замена с «HTTPS из коробки» — **App Platform**: платформа сама выдаёт технический домен
с сертификатом Let's Encrypt и умеет переменные окружения. Приёмник у нас уже написан, менять код
не нужно — он тем же файлом уходит в контейнер (см. `Dockerfile` в корне репозитория).

## Что нажать (7 шагов, ~5 минут)

1. Откройте **https://timeweb.cloud/my/apps** (раздел **App Platform**) → кнопка **«Создать»**.
2. Подключите **GitHub** и выберите репозиторий **`vanyaka229/sd-site`**, ветка **`main`**.
3. Framework / тип сборки: **Dockerfile**.
   Поле **«Путь до директории проекта»** оставьте **пустым** — Dockerfile лежит в корне репозитория.
4. Регион и конфигурация: **минимальный тариф** (приёмнику хватает 1 ГБ RAM и 1 vCPU; нагрузка —
   несколько заявок в день).
5. **Показать расширенные настройки**:
   * **Путь проверки состояния**: `/health`
   * **Переменные** (Настройки → Переменные) — три штуки:

     | Имя | Значение |
     | --- | --- |
     | `TG_BOT_TOKEN` | токен бота `@sddance_journal_bot` (тот же, что в `js/main.js`) |
     | `TG_CHAT_ID` | `8653239953` (это `@sd_dancestudio`) |
     | `ALLOWED_ORIGINS` | `https://sd-dance-st.ru,https://www.sd-dance-st.ru,http://localhost` |

     `HOST=0.0.0.0` и `PORT=8080` задавать не нужно — они уже стоят в Dockerfile.
6. **Запустить деплой** и дождаться зелёного статуса (первая сборка — 2–5 минут).
7. На вкладке **«Дашборд»** найдите **технический домен** вида `https://<имя>.twc1.net` и
   **пришлите его координатору** — после этого адрес вписывается в сайт одной строкой
   (`BOOKING_SERVER` в `js/main.js`), и заявки начинают уходить через приёмник.

## Сколько это стоит

* **Frontend-приложения** в App Platform тарифицируются по запросам (0,000495 ₽ за запрос,
  4,95 ₽ за 10 000 запросов) — наш случай **не этот**.
* **Backend-приложение** (наш случай: приёмник отвечает на `POST /tg`) разворачивается на
  облачном сервере, то есть оплачивается **по тарифу выбранной конфигурации** — точную сумму
  панель покажет на шаге 4 до создания приложения. **Бесплатного тарифа для backend нет.**
* Если платить не хочется, есть два бесплатных пути — см. ниже.

## Бесплатные альтернативы (если платить не хочется)

**A. Освободить порт 443 на имеющемся VPS.** Тогда работает уже собранный и проверенный приёмник
(`deploy/vps-receiver/`, юнит systemd + nginx + сертификат). Стоимость 0, работы ~10 минут.
Сейчас 443 занят VPN-контейнером Amnezia (xray/Reality, он же предъявляет чужой сертификат
`*.google-analytics.com` — это маскировка VPN, а не поломка). По фактам с сервера VPN выглядит
неиспользуемым: за 11 дней работы **ни одного рукопожатия** AmneziaWG (у обоих пиров
`latest handshake = 0`, трафик 0 байт), в ядре **нет ни одной IPsec-SA**, текущих соединений на
443 — ноль. Решение за владельцем: если VPN не нужен, 443 отдаётся сайту.

**B. Бесплатный внешний serverless** (Cloudflare Workers, Vercel, Deno Deploy) — HTTPS и переменные
окружения там из коробки, но это ещё один аккаунт и ещё одна площадка. Код приёмника переносится
почти без изменений: нужен лишь адаптер «запрос → ответ» под конкретную платформу.

## Что готово с нашей стороны

* `deploy/vps-receiver/tg-receiver.js` — приёмник (Node, без зависимостей): проверка метода и
  `Content-Type`, лимит тела 16 КБ, белый список Origin, экранирование для Telegram, таймаут 10 с,
  `{"ok":true}`, ограничение частоты 10 запросов/мин с IP, защита от дублей по телефону.
  Протестирован локально: 24 сценария, все зелёные (`sd-studio-design/tools/test_vps_receiver.cjs`).
* `Dockerfile` в корне репозитория — собирает тот же файл приёмника, слушает `0.0.0.0:8080`,
  есть `EXPOSE` и `/health`.
* Сайт: `js/main.js` сначала пробует приёмник, потом `api.telegram.org`, потом мягкий режим с
  кнопкой. Адрес — константа `BOOKING_SERVER`.
